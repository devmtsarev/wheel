# API колеса призов

Спецификация: [`openapi.yaml`](openapi.yaml) (OpenAPI 3.1). Здесь то, что в схему не помещается:
подпись запросов, порядок вращения, вебхуки, WebSocket и доступ виджета.

## Доступ и подпись

- **Лицензионный ключ.** `Authorization: Bearer wl_...` — выдаётся платформе при подписании
  договора. Один ключ = одна платформа + её секрет подписи + секрет вебхуков. Ключ отзываем.
- **Подпись запроса.** Каждый запрос несёт `X-Wheel-Timestamp` (unix-секунды) и
  `X-Wheel-Signature`:

  ```
  sig = hex( HMAC-SHA256( secret, "{timestamp}.{METHOD}.{path}.{hex(sha256(body))}" ) )
  ```

  `path` — с `/v1`, без хоста и query; у GET вместо хеша тела — хеш пустой строки.
  Окно времени ±300 секунд, повтор с тем же `timestamp` и телом допустим (идемпотентность
  решает `Idempotency-Key`).
- **Идемпотентность.** Все POST несут `Idempotency-Key`. Повтор с тем же ключом возвращает
  первый результат, ничего не выполняя заново. Срок хранения ключей ≥ 24 ч.
- **Лимиты частоты.** По ключу: 20 rps на чтение, 5 rps на запись, всплеск ×2 на 10 с.
  Превышение — 429 с `Retry-After`.

## Порядок вращения

```
зритель        виджет           вендор                 платформа            модель
  │ клик         │                 │                       │                  │
  │─────────────▶│ POST /spins     │                       │                  │
  │              │────────────────▶│ допуск, цена 30 с,    │                  │
  │              │                 │ commit сида           │                  │
  │              │                 │── charge.reserve ────▶│ резерв токенов   │
  │              │                 │◀──── 200 ok ──────────│                  │
  │              │                 │  POST /spins/{id}/commit (платформа)     │
  │              │                 │ розыгрыш HMAC         │                  │
  │              │                 │── charge.commit ─────▶│ списание         │
  │              │                 │── spin.result ───────▶│ лента чата       │
  │              │◀── WS result ───│ приз в очередь ───────┼─────────────────▶│
  │ анимация     │                 │ server_seed раскрыт   │                  │
```

- Цена фиксируется на 30 секунд (`price_valid_for_s`). Если зритель подтвердил позже —
  409 `price_changed`, виджет показывает новую цену и спрашивает согласие заново.
- Розыгрыш происходит ровно один раз, после подтверждения оплаты. До него вероятности и цена
  вращения не меняются; динамика цены действует только между вращениями.
- Отмена возможна только до розыгрыша (`/spins/{id}/cancel` → `charge.release`). Если
  подтверждение не пришло до `reserve_expires_at`, вращение само уходит в `expired`,
  резерв снимается тем же `charge.release`.
- Правило допуска перед продажей: активная версия есть, очередь короче `queue_limit`,
  `время до конца эфира ≥ очередь + худший приз + buffer_s`. Иначе 409 с причиной —
  виджет показывает «колесо на паузе», а не ошибку.

## Вебхуки (вендор → платформа)

- URL и секрет вебхуков фиксируются на платформу. Каждый вызов несёт `X-Wheel-Event-Id`,
  `X-Wheel-Timestamp`, `X-Wheel-Signature` (та же формула подписи, `path` — путь приёмника).
- Ответ 200 — доставлено. Иное/таймаут — повторы с экспоненциальной задержкой:
  1 с, 10 с, 60 с, 5 мин, 30 мин, далее каждый час до 24 ч. Повторы несут тот же `event_id`;
  платформа обязана дедуплицировать.
- `charge.reserve` — особый случай: это синхронная часть создания вращения. Нет 200 за 5 с —
  вращение не продаётся (зритель видит «попробуйте ещё раз»), повторов нет.
- Порядок не гарантируется, кроме пары reserve→commit/release одного вращения.

## WebSocket для виджета

`wss://api.wheel.example.com/v1/ws?wheel={wheel_id}&viewer={viewer_id}&token={widget_token}`

События сервера (JSON, поле `type`):

| type            | Когда                                 | Полезная нагрузка |
| --------------- | ------------------------------------- | ----------------- |
| `price.changed` | Шаг динамической цены                 | `price`, `valid_for_s` |
| `wheel.paused`  | Очередь полна или эфир заканчивается  | `reason` |
| `wheel.resumed` | Пауза снята                           | — |
| `spin.created`  | Начало вращения (для анимации у всех) | `spin_id`, `viewer_id` |
| `spin.result`   | Результат                             | `spin_id`, `item_name`, `item_price`, `roll_ppm`, `server_seed_hash` |
| `queue.updated` | Изменилась очередь                    | `length`, `limit` |

Клиент шлёт только `ping`; всё управление — через REST. При обрыве виджет переподключается
с нарастающей задержкой и перечитывает `GET /wheels/{id}/public`.

**Fallback postMessage.** Если платформа не даёт виджету исходящий WS (строгая CSP), виджет
работает через `window.postMessage` с родительской страницей, а страница платформы
проксирует те же JSON-события из своего соединения. Формат сообщений идентичен WS.

## Доступ виджета

Виджет работает в браузере зрителя и не может нести лицензионный ключ. Платформа выдаёт ему
короткоживущий `widget_token` (JWT, ≤ 15 мин, подписан секретом платформы), в котором
`wheel_id`, `viewer_id`, `exp`. С ним доступны только `GET /wheels/{id}/public`,
`POST /spins`, `GET /spins/{id}`, `GET /spins/{id}/fairness` и WS. Всё остальное — только
с ключом платформы.

## Ошибки

`code` в теле ошибки стабилен: `invalid_signature`, `stale_timestamp`, `idempotency_conflict`,
`price_changed`, `queue_full`, `stream_ending`, `wheel_inactive`, `validation_failed`,
`rate_limited`, `not_found`. Текст `message` может меняться, коды — нет.
