## 3. Математика

- [ ] «Общие» призы: часть призов видят все зрители эфира, а не только выигравший
  - [ ] Разделить призы на личные (ответ на вопрос, комплимент) и общие (танец, смена образа)
  - [ ] Ценность общего приза для зала: платит один, получают все — как это меняет спрос и каннибализацию меню
  - [ ] Эффект «подожду, пока прокрутит кто-то другой» и обратный эффект — азарт зала
  - [ ] Нужна ли складчина: общий прогресс к призу вместо личного вращения
  - [ ] Как учитывать общие призы в шансах, цене и ёмкости модели
- [ ] Каннибализация в новых частях модели (в базовом расчёте цены она есть: c = c0 + φ/k)
  - [ ] Динамическая цена: сейчас цель — заполнить ёмкость модели, каннибализация не учитывается; ступень вниз увеличивает долю c, поэтому решение должно опираться на прирост выручки, а не только на загрузку
  - [ ] Сервисная каннибализация по пунктам φ_i: пункты, которые зритель и так купил бы по меню, разные; тогда выгода платформы зависит от формы шансов, а не только от S и EV — это влияет на выбор a_i и k_i
  - [ ] Лояльность k_i: пункт с высоким φ_i дешёвым делать невыгодно — добавить это в правило выбора k_i
  - [ ] Скрипт симуляции считает выгоду с каннибализацией, а не только выручку колеса
- [ ] Подбор шансов по данным
  - [ ] Зависимость спроса от шанса выигрыша и заметности джекпота — измерить в пилоте
  - [ ] Оптимизатор шансов поверх `variants`, когда появятся данные
  - [ ] Правило правки под валидатор: сейчас двигаются только самый дешёвый и самый дорогой пункт
- [ ] Затраты и маржа по пунктам
  - [ ] Откуда брать μ_i: по длительности приза или по оценке модели
  - [ ] Риск серии при разных μ_i в основном расчёте коридора (функции есть, в `base` не подключены)
- [ ] Динамическая цена
  - [ ] Проверить предиктивную модель на симуляции эфира: пики, спад, короткий эфир
  - [ ] Изменение k_i на лету: какие пункты дорожают при перегрузке
- [ ] Скрипт симуляции (шаг 5 исходного плана)
  - [ ] Монте-Карло на 10^6 вращений для любой конфигурации
  - [ ] Симуляция пилота с контрольной группой: какая доля прироста вендору даёт платформе ROI ≥ 3–4
